# 接口契约 · SeeDance × 启元T1 展会演示系统

> **用途**：三方（机器人 / 前端 / 后端）联调的**唯一对接基线**。一经确认即「冻结」，改字段须通知其余各方并升版本号。
> **冻结目标日**：2026-10-09　|　**契约版本**：v2.0（WebSocket 优先）　|　**关联**：`技术设计-展会演示系统对接.md`
>
> **v2.0 架构变更（2026-10-08 决策）**：不上独立服务器，改由**机器人主板上的 Python 程序当「中转站」**（开 WebSocket 服务），展示页面做 **WS 客户端**，**由机器人 Python 直连 SeeDance 生成、密钥不进浏览器**。视频交付走**上游直链**。原 HTTP 轮询 / Java 后端方案降为**附录 A 备选**。

## 0. 通用约定（WebSocket 版）

| 项 | 约定 |
|---|---|
| 传输 | **WebSocket**（RFC6455），文本帧承载 JSON，`UTF-8` 编码 |
| 角色 | **机器人 Python = WS 服务端**（监听 `:8765`）；**展示页面 = WS 客户端**（连 `ws://<机器人IP>:8765`）|
| 寻址 | 页面地址由 URL 参数给：`?ws=ws://<IP>:<端口>` 或简写 `?robot=<IP>`（端口默认 8765）|
| 消息封装 | 每条一个 JSON 对象，必带 `type` 字段区分类型；字段只追加不重命名 |
| 轮次 `round` | 整数。机器人每接一位新访客 `+1`，并在**该轮所有消息**里带上；页面据此识别「新一轮」并丢弃过期轮次的终态 |
| 时间 `time` | 字符串 `HH:MM`（24 小时制，机器人本地时区）|
| 并发 | **一轮只跑一个**：机器人在发出上一轮终态（`video_ready`/`video_failed`）前，不再发新的 `chat(user)` |

## 1. 连接与生命周期

1. **建连**：页面打开即连 `ws://<机器人IP>:8765`；连上后机器人可发 `{type:'system',online:true}`，页面底部状态灯转绿。
2. **断线重连**：页面是客户端，`onclose` 后每 **2 秒**自动重连，直到成功；期间状态灯标红「机器人不可达」。
3. **心跳**：页面每 **5 秒**发 `{type:'ping'}`，机器人回 `{type:'pong'}`。（TCP 半开时靠心跳/重连兜底。）
4. **超时兜底（双向，防大屏卡死）**：
   - 机器人侧：单轮从 `chat(user)` 起，**≤ 90 秒**必须发终态；拿不到结果就发 `video_failed`。
   - 页面侧：起轮后自持假进度，若**长时间（默认 90 秒）**没收到终态，自动回落待机，等下一位访客。

## 2. 消息协议（核心，冻结项）

### 2.1 机器人 → 页面

**① 访客说了一句（起新一轮）**
```json
{ "type": "chat", "round": 5, "role": "user", "text": "帮我生成一个海边日落的视频", "time": "14:32" }
```
> 页面动作：`round` 变化 → 清空对话、`demoRunning=true`、**自持假进度**（0→95% 保持）；渲染左侧访客气泡。

**② 机器人固定话术**
```json
{ "type": "chat", "round": 5, "role": "bot", "text": "好的，我已收到您的请求，正在为您生成视频，请稍候。", "time": "14:32" }
```
> 页面动作：渲染右侧机器人气泡。**这句由机器人发**，页面不自动生成，避免重复气泡。

**③ 视频就绪（上游直链）**
```json
{ "type": "video_ready", "round": 5, "url": "https://ark-xxx.tos.../video.mp4?sig=..." }
```
> 页面动作：进度→100% → 完成态(约3s) → `<video>` 播放 `url`。
> 🔴 `url` 为 **SeeDance 返回的上游直链**（本方案不转存）：播放时**笔记本必须能出外网**；上游链接可能带签名有效期，须在就绪后尽快播放。页面播放失败会自动切本地兜底视频（`CONFIG.fakeVideo`）。

**④ 生成失败 / 超时**
```json
{ "type": "video_failed", "round": 5, "reason": "upstream_error" }
```
> 页面动作：不放失败提示、不外露链路断了，直接**轮流播放离线预录兜底片**（`CONFIG.fallbackVideos`，放 `assets/fallback/` 下），播完回待机接下一位访客；仅当兜底片一条都没放进来时才回落待机。`reason` 供日志，页面不细分展示。

**⑤ 在线状态（可选）**
```json
{ "type": "system", "online": true }
```

### 2.2 页面 → 机器人

**① 手动发一句话**（彩排/演示时不靠语音，控制面板「发送指令」触发）
```json
{ "type": "send", "text": "帮我生成一个海边日落的视频" }
```
> 机器人动作：视同访客说了一句话 → 起新一轮（发 `chat(user)`+`chat(bot)`+终态）。

**② 心跳**
```json
{ "type": "ping" }
```
> 机器人动作：回 `{ "type": "pong" }`。

### 2.3 消息一览

| type | 方向 | 关键字段 | 页面动作（现成函数） |
|---|---|---|---|
| `chat` | 机→页 | `round, role, text, time` | `addMsg()`；`role=user` 且新 `round` → 起假进度 |
| `video_ready` | 机→页 | `round, url` | 100% → 完成 → `playVideo(url)` |
| `video_failed` | 机→页 | `round, reason` | 轮流放离线兜底片 → 播完回待机（无兜底片则直接回待机）|
| `system` | 机→页 | `online` | 底部状态灯 |
| `send` | 页→机 | `text` | 机器人起一轮 |
| `ping` / `pong` | 双向 | — | 心跳/在线判定 |

## 3. 约定细则（逐条对齐）

1. **假进度谁做**：SeedDance 不报百分比 → **进度由页面自持**（`chat(user)` 起，爬到 95% 保持，绝不自动到 100%）。机器人**不发 progress**，只发终态。
2. **固定话术谁发**：机器人发 `chat(bot)`（§2.1②），页面只渲染。
3. **轮次隔离**：机器人每轮 `round+1` 并在该轮所有消息带上；页面遇新 `round` 清空重开，遇**过期 `round` 的终态直接丢弃**。
4. **断句/触发时机**：观众说完话由**机器人语音识别决定何时算一句**，然后才发 `chat(user)`；页面不管语音，只等这条消息。（= 待确认 A6）
5. **上游直链**：本方案**不转存**，`video_ready.url` 直接给上游地址。代价：播放依赖外网 + 链接可能过期；页面已内置播放失败切本地兜底。
6. **协议只加不改**：字段冻结后只追加不重命名；改协议须通知前端并升契约版本号。

## 4. 生成参数（机器人 Python 侧固定，2026-10-08 决策）

- **时长固定默认 15s**：不解析访客口语秒数（访客说「30 秒」只当描述文字进 prompt）。
- **比例固定 16:9**；模型走机器人侧配置。
- 依据：SeeDance 2.5 单次 ≤ 30s；实时链路只用单次生成，不做多轮续写（续写=分钟级，与展会「快」冲突；长片走离线预生成）。

## 5. 各方职责边界（一句话）

| 方 | 只做 | 不做 |
|---|---|---|
| 机器人（Python）| 语音转文字 → 发 `chat(user)`+`chat(bot)` → **调 SeeDance** → 发 `video_ready`/`video_failed` | ❌ 前端动画节奏 |
| 展示页面 | 连 WS → 按 `type` 渲染 + 自持假进度 + 播放 + 手动 `send` | ❌ 持密钥 ❌ 直连 SeeDance |
| SeeDance | 被机器人 Python 调用生成视频 | — |

> **密钥铁律**：SeeDance API 密钥**只存在于机器人 Python（主板）侧**，绝不进浏览器页面、不进 HTML 文件、不进 Git。本方案相比「页面直连」正为此而设。

## 附录 A · 备选方案：Java 后端 HTTP 轮询（密钥在后端，页面轮询 state）

> 若机器人团队无法在 Python 里调 SeeDance，则回到本备选：**已写好的 morai-server `exhibition` 模块**当后端中转（免计费直连 provider + 转存出免登录播放地址），机器人只 `POST {text}`，页面每 0.5s 轮询 `GET /api/v1/demo/state`。密钥在后端、视频走我方转存地址（不外露上游 URL）。

| 接口 | 方法 | 请求 | 响应（Result 信封 `{code,msg,data}`）|
|---|---|---|---|
| `/api/v1/demo/submit` | POST | `{text}` + `Authorization: Bearer <token>` | `data:{round, accepted, reason}`；受理看 `accepted` 不看 HTTP 码 |
| `/api/v1/demo/state` | GET | 无（`?_=<ts>` 防缓存）| `data:{round, phase, messages[], videoUrl}`，`phase`∈`idle/generating/ready/failed`，`videoUrl`=我方转存地址 |

- 页面用 `?live=1`（或 `?mode=live&poll=<url>`）即切到此模式；`handleState()` 已实现（`round` 变化重渲染、`phase=ready` 播放、`failed` 回落）。
- 后端模块位置：`morai-service/.../exhibition/DemoService.java` 等（已存档 commit `3ed038a`，编译 + 6 个单测通过）。启用前需配 `EXHIBITION_DEMO_VIDEO_MODEL / SUBMIT_TOKEN / OWNER_USER_ID`，并备一台能跑 MySQL+Redis 的机器。
- 详细字段口径见本文件 v1.0 历史版本与 `技术设计-展会演示系统对接.md` §4/§6。
